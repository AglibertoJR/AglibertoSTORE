# AglibertoStore — Roadmap de Desenvolvimento e Aprendizado

O roadmap abaixo é orientado para **aprendizado rápido com foco em empregabilidade**.

## Fase 0 — Preparação

- Definir arquitetura
- Definir módulos/domínios
- Definir banco inicial
- Configurar Git/GitHub
- Criar README inicial

## Fase 1 — Java aplicado ao projeto

- Revisão rápida do necessário
- Organização de classes
- Interfaces
- Exceptions aplicadas
- Collections e Streams quando realmente necessários

## Fase 2 — Spring Boot

- Criar projeto
- Entender estrutura
- Injeção de dependência
- Controllers
- Services
- Repositories
- Configuração

## Fase 3 — REST API

- HTTP
- GET/POST/PUT/PATCH/DELETE
- Status codes
- DTOs
- Validation
- Exception handling
- Swagger/OpenAPI

## Fase 4 — Banco de dados

- PostgreSQL
- Modelagem relacional
- Relacionamentos
- JPA/Hibernate
- Migrations com Flyway
- Consultas e paginação

## Fase 5 — Autenticação

- Spring Security
- Password hashing
- BCrypt
- Login
- JWT
- Access token
- Refresh token

## Fase 6 — Autorização

- Roles
- RBAC
- CUSTOMER
- ADMIN
- Proteção de endpoints
- Testes de autorização

## Fase 7 — E-commerce backend

- Produto
- Categoria
- Estoque
- Carrinho
- Pedido
- Item do pedido
- Status do pedido
- Usuário

## Fase 8 — Pagamentos

- Stripe
- Payment Intent / Checkout
- Webhooks
- Confirmação de pagamento
- Idempotência e segurança básica

## Fase 9 — Frontend

- React
- TypeScript
- Componentes
- Rotas
- Estado
- Formulários
- Integração com API
- Autenticação no frontend
- Área administrativa

## Fase 10 — Testes

- JUnit 5
- Mockito
- MockMvc
- Testes de serviços
- Testes de controllers
- Testes de autenticação/autorização
- Testcontainers

## Fase 11 — DevOps

- Docker
- Docker Compose
- Variáveis de ambiente
- GitHub Actions
- Build/test pipeline
- SonarQube

## Fase 12 — Deploy

- Preparar produção
- Banco em cloud
- Backend em cloud
- Frontend em cloud
- Stripe em ambiente seguro
- Logs e observabilidade básica

## Fase 13 — Portfólio

- README profissional
- Arquitetura documentada
- Screenshots
- Swagger
- Demonstração
- Histórico de commits organizado
- Descrição para currículo
- Descrição para LinkedIn
- Preparação para entrevista técnica

## Regra de avanço

Não avançar apenas porque a funcionalidade "funciona".

Avançar quando:
- você entende o conceito principal;
- a implementação funciona;
- os testes relevantes passam;
- a documentação necessária foi atualizada;
- o commit lógico foi feito.
